🛡️ Unit 1: Fundamentals of Ethical Hacking & Cyber Laws

Core conceptual accelerator covering authorization boundaries, Indian legal frameworks, the 5-phase lifecycle, ethical tool ecosystems, and risk calculation models.

📌 1.1 Scope, Legality & Indian Cyber Law Framework

  • Ethical Hacking vs Penetration Testing: Ethical Hacking is the overarching discipline of utilizing adversary techniques under explicit authorization to identify vulnerabilities, assess real risk, and assist asset owners in remediation. Penetration Testing (PT) is a specific, goal-oriented methodology that safely validates whether identified weaknesses can be chained to compromise assets within an agreed boundary.
  • Rules of Engagement (ROE): The formal operational contract defining target IP addresses/URLs, testing timeframes, prohibited techniques (e.g., DoS, data exfiltration), synthetic test accounts, emergency stop contacts, and evidence-handling rules. A classroom assignment does not grant permission to scan or test university or public networks.
  • Information Technology Act, 2000 (India):
    • Section 43: Civil penalty for unauthorized computer access, downloading, copying, extraction of data, or introducing computer contaminants.
    • Section 66: Criminal liability (imprisonment up to 3 years and fine up to ₹5 lakh) for any dishonest or fraudulent act under Section 43.
    • Section 66C & 66E: Criminalization of identity theft, stolen credentials, and violation of bodily privacy.
    • Section 70: Severe penalties (up to 10 years imprisonment) for unauthorized access to declared Critical Information Infrastructure (CII).
  • DPDP Rules 2025 (Digital Personal Data Protection): Mandates that Data Fiduciaries enforce robust organizational safeguards for citizen data, restrict testing to synthetic data, and report cybersecurity incidents to CERT-In within strictly prescribed time windows (typically 6 hours).

🔄 1.3 The 5-Phase Attack & Ethical Audit Lifecycle

  • Phase 1 · Reconnaissance (Footprinting): Gathering public, open-source, and target intelligence. Passive Reconnaissance uses public registries (Whois, Shodan, Google Dorking, Netcraft, Maltego) without generating traffic against the target. Active Reconnaissance directly probes target DNS servers (zone transfer requests) or network boundaries, requiring explicit scope.
  • Phase 2 · Scanning & Enumeration: Mapping live assets and service surfaces. Involves host discovery (ICMP ping sweeps), TCP/UDP port scanning, OS fingerprinting, and application service querying. Enumeration extracts specific target metadata: usernames, Windows shares (SMB), SNMP community strings, network routing tables, and banner version strings.
  • Phase 3 · Gaining Access (Exploitation Validation): Proving that a hypothesized vulnerability can be leveraged. In ethical engagements, testers use minimal, non-destructive proofs-of-concept (e.g., executing a calculator or obtaining an unprivileged echo shell) to validate realistic business impact without disrupting uptime.
  • Phase 4 · Maintaining Access (Persistence Analysis): Attackers establish persistent access via backdoors, scheduled cron jobs, rootkits, or secondary administrative accounts. In ethical testing, persistence is simulated strictly in disposable sandbox labs to test endpoint detection (EDR), with all changes cleanly documented and rolled back.
  • Phase 5 · Covering Tracks (Defensive Evidence Management): While adversaries tamper with event logs, overwrite timestamps (timestomping), or delete shell histories to conceal intrusion, ethical professionals do the opposite: they preserve immutable audit trails, record exact command timestamps, and disclose all activities to verify SIEM detection coverage.
🇮🇳 FOR BKL Mukul Explains · 1.3 Hacking Ke 5 Phases Ka Step-by-Step Flow
  1. Phase 1: Reconnaissance (Footprinting): Target ke baare me jaankari nikaalna (Google Dorking, WHOIS, DNS harvesting). Target ko pata nahi chalta.
  2. Phase 2: Scanning & Enumeration: Live hosts, open ports (80, 22), aur software versions (Apache, OpenSSH) scan karna using Nmap.
  3. Phase 3: Gaining Access (Exploitation): Flaw dhoondh kar Metasploit ya payload se shell command prompt lena.
  4. Phase 4: Maintaining Access: Root/Admin privilege lena aur backdoor banana taaki server reboot ke baad bhi connection na toote.
  5. Phase 5: Clearing Tracks & Reporting: Temporary artifacts delete karna aur client ko detailed audit report dena (How to patch).

🔍 1.5 Nmap Port Scanning Mechanics & Reconnaissance Operators

Scan Type / Operator CLI Flag / Syntax Mechanism & Packet Behavior Exam Relevance & Trade-off
TCP SYN Stealth Scan nmap -sS <target> Sends SYN; receives SYN-ACK (open) or RST (closed); sends RST immediately to abort 3-way handshake Default root scan. Stealthy because TCP socket never establishes; evades application-layer daemon logging
TCP Connect Scan nmap -sT <target> Completes standard 3-Way Handshake via OS network socket API (SYN → SYN-ACK → ACK) Usable without root/raw-socket privileges; slower, easily detected, and heavily logged by target firewalls/services
UDP Port Scan nmap -sU <target> Sends empty UDP packets; ICMP Port Unreachable (Type 3 Code 3) indicates closed; no reply indicates open|filtered Essential for discovering DNS (53), SNMP (161), DHCP (67/68); slow due to operating system ICMP rate limiting
Service Version Probe nmap -sV <target> Interrogates open ports with signature payloads; matches banners against `nmap-service-probes` database Identifies unpatched software versions regardless of whether service runs on non-standard ports (e.g. SSH on 2222)
OS Fingerprinting nmap -O <target> Analyzes subtle TCP/IP stack implementation nuances (initial TTL, window size, TCP options, IP ID generation) Determines target operating system to narrow exploit payloads; can be skewed by packet scrubbers or load balancers
Vulnerability NSE Script nmap --script vuln <target> Executes Lua scripts from Nmap Scripting Engine to detect known CVE vulnerabilities and service misconfigurations Automates non-destructive detection; high-intensity scripts can trigger intrusion alarms or destabilize legacy daemons
  • Google Dorking (Passive OSINT Reconnaissance):
    • site:target.com — Limits query scope strictly to target organization domains.
    • filetype:pdf | env | sql | log | xlsx — Discovers leaked credential files, environment configurations, and database dumps.
    • intitle:"Index of /" — Pinpoints servers with active directory indexing enabled, exposing internal file systems.
    • inurl:admin | inurl:login | inurl:dashboard — Uncovers unlinked administrative backdoors and login portals.
🇮🇳 FOR BKL Mukul Explains · 1.5 Nmap Flags Ka Formula

Nmap ke yeh 5 flags viva aur practical exam me 100% poochhe jaate hain:

  • -sS: SYN Stealth Scan — Half-open scan; handshake poora kiye bina connection reset (RST) karta hai taaki server logs me shor na mache!
  • -sV: Version Detection — Port pe chal rahe software ka exact version batata hai.
  • -sC: Default Scripts — Nmap Scripting Engine (NSE) ke safe scripts chalata hai.
  • -O: OS Detection — TCP/IP fingerprint se target ka OS (Linux vs Windows) batata hai.
  • -p-: All Ports — Port 1 se 65535 tak saare ports scan karta hai.

📊 1.6 Risk Calculation & Professional Reporting Architecture

  • Quantitative Risk Formula: $$\text{Risk} = \text{Threat} \times \text{Vulnerability} \times \text{Impact}$$ A critical vulnerability on an isolated host without an active threat agent presents lower real risk than a medium vulnerability on a public-facing authentication portal.
  • CVSS v3.1 Scoring Metrics: Evaluates vulnerability severity across Base Metrics (Attack Vector, Attack Complexity, Privileges Required, User Interaction, Scope, Confidentiality, Integrity, Availability), Temporal Metrics (Exploit Code Maturity, Remediation Level), and Environmental Metrics (Modified Base Metrics in target organization).
  • 7 Mandatory Components of a Penetration Test Report:
    1. Executive Summary: High-level business impact, strategic risk overview, and prioritized roadmap for leadership.
    2. Methodology & Scope Confirmation: Contract dates, tested IPs/domains, and explicit exclusions.
    3. Vulnerability Title & Severity Rationale: Standardized identifier (CVE/CWE) and CVSS rating justified in context.
    4. Reproducible Technical Steps: Clear, deterministic narrative enabling client engineers to replicate the finding.
    5. Sanitized Evidence: Redacted HTTP requests/responses, console screenshots, and proof-of-concept output.
    6. Specific Technical Remediation: Configuration directives, code-level patches, and defensive architectural controls.
    7. Retest & Verification Procedure: Explicit criteria to validate that the fix works and does not introduce side-effects.
🇮🇳 FOR BKL Mukul Explains · 1.6 Risk Calculation & Pentest Report

Cybersecurity me risk ka official mathematical formula:

$$\text{{Risk}} = \text{{Threat (Khatra)}} \times \text{{Vulnerability (Kamzori)}} \times \text{{Impact (Nuksan)}}$$
• Agar server internal private network pe hai aur bahar se unreachable hai (Threat kam), toh vulnerability hone par bhi overall Risk drastically kam ho jata hai!
• Audit Report Format: Executive Summary (CEO ke liye high-level) → CVSS v3.1 Severity Score (0.1 se 10.0) → Step-by-Step Proof of Concept (PoC) → Concrete Remediation Patch Code.

🛡️ 2.1 Perimeter Defenses & Network Filtering Architecture

Security Technology OSI Layer Operational Placement Primary Function & Detection Logic Critical Limitation
Packet Filtering Firewall (Stateless) Layer 3 / 4 Perimeter router or border interface Filters packets based on static rules: Source/Dest IP, Source/Dest Port, Protocol (TCP/UDP/ICMP). Evaluates each packet in isolation Cannot track connection states; vulnerable to spoofed ACK flags and fragmented packet attacks
Stateful Inspection Firewall (SPI) Layer 3 / 4 Perimeter boundary, DMZ border Maintains a state table tracking active TCP handshakes (SYN, SYN-ACK, ACK) and UDP sessions; automatically permits valid returning packets Cannot inspect application layer payloads or detect attacks tunneling through allowed ports (e.g. port 80/443)
Next-Generation Firewall (NGFW) Layer 3 to 7 Corporate edge, datacenter ingress Combines SPI with Deep Packet Inspection (DPI), integrated IPS, user-identity awareness, and TLS decryption inspection High resource overhead; SSL inspection requires installing enterprise root certificates on all endpoints
IDS (Intrusion Detection System) Layer 3 to 7 Out-of-band via network TAP or switch SPAN mirror port Passively inspects a copy of network traffic; compares against known signatures (Snort/Suricata) or behavioral anomalies; generates alerts Passive only; cannot terminate or block attacks inline. High rate of false positives if signatures are not tuned
IPS (Intrusion Prevention System) Layer 3 to 7 Inline directly in the live traffic path Actively monitors traffic passing through; immediately drops malicious packets, resets TCP connections (`TCP RST`), and updates firewall rules Single point of failure/latency if overloaded; false positives directly drop legitimate corporate business traffic
VPN (Virtual Private Network) Layer 3 / 4 Gateway-to-gateway or client-to-gateway Establishes an authenticated, encrypted tunnel across untrusted networks using IPsec (AH/ESP) or SSL/TLS (WireGuard, OpenVPN) Protects data in transit only; does not protect against compromised endpoints or attacks launched inside the private network
Forward Proxy vs Reverse Proxy Layer 7 Forward: client egress. Reverse: server ingress Forward proxies enforce employee URL filtering, caching, and client anonymity. Reverse proxies handle load balancing, SSL termination, and WAF inspection Misconfiguration can create open relay proxies or introduce single points of server failure
🇮🇳 FOR BKL Mukul Explains · 2.1 Firewalls, IDS, IPS aur Proxies
  • Stateless vs Stateful: Stateless har packet ko static rules pe akele dekhta hai (fake ACK flag se fool ho jata hai). Stateful dynamic Connection State Table maintain karta hai; unsolicited packets turant DROP!
  • NGFW (Next-Gen): Layer 7 Deep Packet Inspection (DPI) karke application pehchanta hai (port 80 pe BitTorrent block karega).
  • IDS vs IPS: IDS passive CCTV camera hai (switch ke SPAN port pe sirf alert deta hai). IPS active inline bouncer hai jo malicious packet live drop karke TCP RST bhejta hai!
  • Reverse Proxy: Nginx web server ke aage baith kar backend IP chupata hai aur SSL load sambhalta hai.

🔄 2.2 The Complete 8-Stage VAPT Workflow Pipeline

  • Stage 1 · Scoping & Legal Sign-Off: Obtain written authorization, non-disclosure agreements (NDA), defined IP subnets, excluded critical servers, and agreed testing timeframes.
  • Stage 2 · Reconnaissance & Asset Discovery: Discover all live hosts, domain assets, subnet allocations, and exposed edge interfaces using passive OSINT and ICMP/ARP sweeps.
  • Stage 3 · Network Scanning & Service Enumeration: Scan open ports using TCP SYN scans (`nmap -sS`), identify exact software versions (`nmap -sV`), and query service-specific protocols (SMB, SNMP, LDAP).
  • Stage 4 · Vulnerability Assessment (Breadth Scan): Run automated vulnerability scanners (OpenVAS, Nessus) to check discovered services against CVE databases and misconfiguration baselines.
  • Stage 5 · Manual Verification & False Positive Elimination: Manually examine scanner findings to discard false positives (Type I errors) and uncover subtle logic flaws missed by automated tools.
  • Stage 6 · Controlled Exploitation Validation: Safely validate selected high-risk attack paths in accordance with the ROE using targeted proof-of-concept scripts to demonstrate realistic business impact.
  • Stage 7 · Comprehensive Reporting & Risk Rating: Author a prioritized technical report with CVSS ratings, executive risk summaries, reproducible evidence, and code/config fixes.
  • Stage 8 · Remediation Retesting & Formal Closure: After the engineering team applies patches, re-run tests against previously vulnerable assets to verify that the remediation is effective and stable.
🇮🇳 FOR BKL Mukul Explains · 2.2 VAPT Ka 8-Stage Audit Pipeline
  1. 1. Scoping & RoE: Boundary aur timing tay karo.
  2. 2. Asset Discovery: Network ke saare active IPs dhoondho.
  3. 3. Automated Scanning: Nessus/OpenVAS se unpatched bugs ki list banao.
  4. 4. False Positive Filtering: Scanner ke jhooth manually pakdo.
  5. 5. Manual Exploitation: PoC exploit chala ke proof dikhao.
  6. 6. Post-Exploitation & Privilege Escalation: Root access test karo.
  7. 7. Risk Prioritization: CVSS v3.1 score assign karo.
  8. 8. Remediation & Re-Test: Sysadmin ko patch batao aur re-test karo.

🎭 2.4 Spoofing & Man-in-the-Middle (MITM) Deep-Dive

Attack Vector Layer Underlying Vulnerability & Mechanism Effective Defensive Controls
ARP Spoofing / Poisoning Data Link (L2) ARP lacks authentication; hosts accept unsolicited gratuitous ARP replies. Attacker broadcasts forged ARP replies mapping gateway's IP to attacker's MAC Dynamic ARP Inspection (DAI) on managed switches, DHCP Snooping, static ARP tables for critical gateways, encrypted application protocols
DNS Cache Poisoning Application (L7) DNS resolvers accepting forged UDP replies containing spoofed Transaction IDs (TXID) before the authentic authoritative server responds DNSSEC (cryptographic record signing), DNS over HTTPS (DoH) / DNS over TLS (DoT), randomized source ports and query IDs
IP Address Spoofing Network (L3) IPv4 does not validate whether source IP matches transmitting host. Used extensively in reflected amplification DoS attacks (NTP, DNS, SNMP) BCP 38 (Ingress/Egress Filtering) at ISPs, Unicast Reverse Path Forwarding (uRPF), cryptographic handshake verification (TCP SYN cookies)
SSL/TLS Stripping (MITM) Transport/App (L4-7) Intercepting proxy intercepts initial unencrypted HTTP redirect, serving cleartext HTTP to client while maintaining HTTPS to server HTTP Strict Transport Security (HSTS) with `preload` directive, Secure cookie flags, eliminating cleartext HTTP entry points entirely
🇮🇳 FOR BKL Mukul Explains · 2.4 ARP Poisoning & MITM Attacks

ARP protocol (RFC 826) stateless hai aur unsolicited Gratuitous ARP pe vishwas karta hai:

  • Attacker victim ko bolta hai: 'Gateway Router ka IP mere MAC pe hai', aur router ko bolta hai: 'Victim ka IP mere MAC pe hai'. Dono ka traffic attacker se pass hota hai!
  • SSL Strip: HTTP se HTTPS ka 302 redirect intercept karke victim ko cleartext HTTP pe rakhta hai.
  • Defenses: Switch pe Dynamic ARP Inspection (DAI) aur web pe HSTS (Strict Transport Security) lagao!

🔒 2.5 IPsec Protocol Suite Architecture: AH vs ESP & Modes

IPsec Component Protocol Number Security Services Provided NAT Compatibility & Packet Behavior
Authentication Header (AH) IP Protocol 51 Data integrity, origin authentication, anti-replay. Hashes immutable fields of outer IP header + payload Fails with NAT: NAT modifies source/dest IP in outer header, immediately invalidating the AH Integrity Check Value (ICV). Provides zero confidentiality (payload is cleartext)
Encapsulating Security Payload (ESP) IP Protocol 50 Confidentiality (AES-CBC/GCM), data integrity, origin authentication, anti-replay. Encrypts payload and appends ICV Compatible with NAT-Traversal (NAT-T): Encapsulates ESP inside UDP port 4500 packets, allowing seamless traversal through stateful NAT firewalls
Transport Mode Host-to-Host Protects Layer 4 payload (TCP/UDP segments) while keeping the original IP header visible and unencrypted Used for direct end-to-end communication between two servers. Lower header overhead; exposes source and destination IP addresses
Tunnel Mode Gateway-to-Gateway / Remote Access Encrypts the entire original IP packet (header + payload) and encapsulates it inside a completely new outer IP header Standard for Site-to-Site VPNs. Conceals internal corporate IP addressing topologies from intermediate public routers and adversaries
🇮🇳 FOR BKL Mukul Explains · 2.5 IPsec AH vs ESP & Modes
  • AH (Authentication Header): Packet integrity aur source authentication deta hai par data ko encrypt nahi karta.
  • ESP (Encapsulating Security Payload): Confidentiality + Integrity dono deta hai (poora data encrypt).
  • Tunnel vs Transport: Tunnel Mode me poora original IP packet encrypt hoke naye IP header me pack hota hai (Site-to-Site VPN). Transport Mode me sirf data payload encrypt hota hai (Host-to-Host).

🔓 2.6 System Security: Privilege Escalation, Backdoors & Trojans

  • Vertical vs Horizontal Privilege Escalation:
    • Vertical: Gaining higher permission levels than assigned (e.g. standard local user elevating to `root` or `NT AUTHORITY\SYSTEM`). Common vectors: kernel vulnerabilities (e.g. Dirty COW), SUID binaries with insecure paths, misconfigured `sudoers` rules (`NOPASSWD`), weak service permissions, unquoted Windows service paths, and DLL search-order hijacking.
    • Horizontal: Accessing resources, data, or functions belonging to peer accounts at the same privilege tier (e.g. user Alice accessing user Bob's financial records via Insecure Direct Object References - IDOR).
  • Backdoors vs Trojans vs Worms:
    • Backdoor: A hidden mechanism, listening service, or undocumented hardcoded credential allowing unauthorized administrative access bypassing standard authentication controls.
    • Trojan Horse: Malicious code disguised as legitimate, benign software (e.g., a utility, game, or driver update). Does not self-replicate; relies on social engineering or user deception to achieve execution.
    • Computer Worm: Autonomous malicious program that actively self-replicates and spreads across network subnets by exploiting unpatched network services (e.g., WannaCry exploiting MS17-010 SMB) without human intervention.
  • System Hardening Checklist: Enforce the Principle of Least Privilege (PoLP), remove unneeded SUID/SGID bits (`find / -perm -4000 -exec ls -ld {} +`), audit administrative rights, implement Role-Based Access Control (RBAC), enforce application allowlisting, and deploy File Integrity Monitoring (FIM / AIDE).
🇮🇳 FOR BKL Mukul Explains · 2.6 SUID Escalation & Rootkits
  • SUID Binaries (chmod 4755): Executable file owner (root) ke privileges se run hoti hai. Command: find / -perm -u=s -type f 2>/dev/null.
  • Agar find, vim, ya nmap pe SUID laga hai, toh GTFOBins trick se 1 second me root shell escape mil jata hai: find . -exec /bin/sh -p \; -quit!
  • Rootkits: Kernel syscalls (jaise sys_getdents64) hook karke processes aur files ko ps aur ls se invisible bana dete hain.

📶 2.7 Wireless Network Security & WPA/WPA2/WPA3 Protocol Cracking

Protocol Standard Cipher & Key Length Authentication Method Vulnerability Profile & Attack Vector Current Recommended Status
WEP (Wired Equivalent Privacy) RC4 stream cipher (64-bit / 128-bit) Open System or Shared Key (pre-shared) Critically flawed 24-bit Initialization Vector (IV). Rapid IV reuse allows passive key recovery within minutes via FMS or ChopChop attacks Completely Broken & Obsolete — Never deploy
WPA (Wi-Fi Protected Access) TKIP cipher (Temporal Key Integrity Protocol) PSK (Pre-Shared Key) or 802.1X Enterprise Uses 48-bit IV and per-packet key mixing, but relies on flawed Michael MIC algorithm vulnerable to Beck-Tews keystream recovery Deprecated & Insecure — Replace with WPA2/WPA3
WPA2 (802.11i) AES-CCMP cipher (Counter Mode CBC-MAC) PSK or 802.1X Enterprise with RADIUS Encryption is robust, but the 4-Way Handshake is vulnerable: capturing Message 1 (ANonce) and Message 2 (SNonce + MIC) allows offline dictionary attacks against weak PSK passphrases using tools like `aircrack-ng` Acceptable with Hardened Passphrases (20+ chars) or Enterprise 802.1X
WPA3 (802.11ax/ac) AES-GCMP-256 (Enterprise) / AES-128 Simultaneous Authentication of Equals (SAE) Replaces 4-Way Handshake with Dragonfly Key Exchange (SAE), providing forward secrecy and mathematical immunity to offline dictionary cracking. Mandates Protected Management Frames (PMF) Modern Industry Standard — Highly Recommended
🇮🇳 FOR BKL Mukul Explains · 2.7 WEP vs WPA vs WPA2 vs WPA3
  • WEP: RC4 cipher + 24-bit IV. 5,000 packets me IV collision hoti hai, FMS attack se 5 minute me crack!
  • WPA: TKIP stopgap fix (48-bit IV). Deprecated.
  • WPA2: AES-128 CCMP encryption. Cipher uncrackable hai par 4-Way Handshake offline brute-force ho sakta hai.
  • WPA3: Dragonfly SAE handshake. Offline dictionary attack impossible; forward secrecy included!

🔑 2.8 WPA2 4-Way Handshake Anatomy & Defensive Hardening

  • Handshake Message Flow:
    • Msg 1 (AP → Client): Access Point transmits ANonce (random authenticator value).
    • Msg 2 (Client → AP): Client generates SNonce, computes the Pairwise Transient Key (PTK) using Pairwise Master Key (derived from PSK), and returns SNonce + Message Integrity Code (MIC).
    • Msg 3 (AP → Client): AP verifies MIC, installs PTK, and sends Group Temporal Key (GTK) with MIC.
    • Msg 4 (Client → AP): Client confirms encryption installation with an acknowledgment frame.
  • Offline Attack Mechanics: An attacker injects deauthentication frames (`aireplay-ng -0`) to disconnect a legitimate client. When the client reconnects, the attacker captures Msg 1 and Msg 2 (`airodump-ng`). The attacker then performs high-speed offline hash matching (`aircrack-ng` or `hashcat` mode 22000) comparing candidate passwords against the captured MIC without interacting with the network.
  • Defensive Hardening Controls: Enforce random passphrases of $\ge 20$ characters (making dictionary attacks mathematically infeasible), deploy 802.1X Enterprise with EAP-TLS certificates, strictly disable Wi-Fi Protected Setup (WPS) to eliminate PIN brute-forcing (Reaver attack), isolate guest clients with VLAN segmentation, and enable Protected Management Frames (PMF / 802.11w).
🇮🇳 FOR BKL Mukul Explains · 2.8 WPA2 4-Way Handshake Ka Cryptographic Khel

Wi-Fi password (PSK) kabhi bhi hawa me transmit nahi hota! Router aur phone 4 messages me dynamic PTK banate hain:

$$\text{{PTK}} = \text{{PRF}}(\text{{PMK}}, \text{{ANonce}}, \text{{SNonce}}, \text{{MAC}}_{{\text{{AP}}}}, \text{{MAC}}_{{\text{{Client}}}})$$
1. Router sends ANonce → 2. Phone generates SNonce, computes PTK + MIC → 3. Router derives PTK, verifies MIC, sends Group Key GTK → 4. Phone confirms.

💻 Unit 3: Application & Web Security Essentials

The core web application triad: comparison of root causes, impacts, and remediation:

Vulnerability Root Cause Primary Impact Definitive Remediation
SQL Injection (SQLi) Concatenating untrusted user input directly into dynamic SQL query strings Database exfiltration, authentication bypass, data tampering Parameterized queries (prepared statements), least-privilege DB accounts
Cross-Site Scripting (XSS) Rendering untrusted data in the browser without proper context-aware encoding Session hijacking, cookie theft, DOM manipulation, credential harvesting Context-aware output encoding, safe DOM APIs (textContent), Content Security Policy (CSP)
Cross-Site Request Forgery (CSRF) Browser automatically submits authenticated session cookies on cross-origin requests Unintended state-changing transactions performed in victim's session context Server-validated anti-CSRF tokens (Synchronizer pattern), SameSite=Strict cookie flag
  • Authentication vs Authorization: Authentication establishes who you are (identity verification); Authorization determines what resources and actions you are permitted to access.
  • OWASP Top 10 Framework: An awareness and prioritization benchmark for web application risks. Be mindful of differences between OWASP 2021 and the newly finalized OWASP 2025.
  • API Security Checklist: Enforce server-side token authentication, validate object-level authorization (BOLA prevention), schema validation, rate-limiting quotas, and TLS transport encryption.
  • Mobile Security Rule: The client device is an untrusted environment. Never embed permanent API secrets in application binaries, and enforce all critical authorization checks on backend servers.

🔒 Unit 4: Advanced Cybersecurity Concepts Essentials

  • Incident Response Flow (NIST SP 800-61): Preparation → Detection & Analysis → Containment → Eradication → Recovery → Lessons Learned.
  • Cryptographic Distinctions:
    • Encryption: Reversible transformation using keys ensuring confidentiality.
    • Hash Function: One-way, fixed-length mathematical digest verifying integrity (cannot be decrypted).
    • Message Authentication Code (MAC): Shared-secret keyed digest providing integrity and authenticity between peers.
    • Digital Signature: Asymmetric private-key signed digest providing non-repudiation and third-party verification.
    • Digital Certificate (X.509): Data structure signed by a trusted CA binding a subject identity to a public key.
  • Hybrid Cryptography: Practical systems (e.g. TLS) use asymmetric algorithms (RSA/ECC) for key establishment and authentication, then switch to fast symmetric ciphers (AES-GCM) for bulk data payload encryption.
  • Advanced Persistent Threats (APTs): Sustained, targeted, well-resourced campaigns by capable adversaries utilizing multi-stage tactics mapped by MITRE ATT&CK. Defenses center on zero trust, endpoint detection (EDR), and active threat hunting.
  • Zero-Trust Architecture (ZTA): "Never Trust, Always Verify." Discards physical network perimeter trust in favor of continuous, context-aware policy evaluations via Policy Decision Points (PDP) and Policy Enforcement Points (PEP).
  • Emerging Attack Surfaces: AI risks (Prompt injection, training data poisoning, insecure tool invocation) and IoT risks (hardcoded credentials, unpatched firmware, lack of host isolation).

🔬 Practical Lab Quick Checklist

  • Pre-Lab Scope & Safety: Document the authorized target URL/IP, test duration, tools permitted, and explicit stop conditions before executing any command.
  • Hypervisor Isolation: Verify that testing virtual machines operate on private Host-Only or Internal networks to prevent traffic leakage onto campus or public networks.
  • Evidence Hygiene: Capture clean, timestamped logs and redact all real personal identifiable information (PII) or credentials from report screenshots.
  • Standardized Report Format: Every syllabus lab submission must include: Aim, Scope & Authorization, Tools Used, Security Theory, Step-by-Step Procedure, Observations, Result, Risks & Limitations, and Remediation Lessons.
