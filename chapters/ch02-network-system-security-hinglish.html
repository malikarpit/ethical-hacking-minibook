§ 2. Unit 2 - Network and System Security

# 2.1 Network security overview

Network security enforces the confidentiality, integrity, and availability (CIA triad) of data across communication pathways. The architecture is analyzed by mapping vulnerabilities and defensive controls to the OSI 7-Layer Reference Model and TCP/IP Protocol Suite:

OSI Layer Core Protocols Primary Attack Vectors Defensive Security Controls
Layer 7 (Application) HTTP/S, DNS, SMTP, FTP, SSH SQL Injection, Cross-Site Scripting, DNS Tunneling, Buffer Overflows Web Application Firewall (WAF), input validation, parameterized queries, TLS 1.3
Layer 4 (Transport) TCP, UDP TCP SYN Floods, Port Scanning (SYN, Xmas, Null), UDP Amplification DDoS Stateful Inspection Firewalls, SYN cookies, connection rate-limiting, TCP reset filtering
Layer 3 (Network) IPv4, IPv6, ICMP, IPsec IP Address Spoofing, Ping of Death, ICMP Smurf attacks, Route Hijacking Ingress/Egress packet filtering (BCP 38), IPsec encryption, ICMP rate limiting
Layer 2 (Data Link) Ethernet, ARP, 802.11 Wi-Fi ARP Poisoning, MAC Flooding, STP Manipulation, 802.11 Deauth frames Dynamic ARP Inspection (DAI), Port Security (MAC limiting), 802.1X Network Access Control
Layer 1 (Physical) Copper, Fiber, Radio (RF) Wiretapping, RF Jamming, unauthorized rogue tap insertion Physical access controls, biometric cage entry, optical fiber intrusion sensors

Defense-in-Depth Principle: A resilient enterprise network avoids relying on a single defensive boundary. It establishes concentric rings of security: perimeter firewalls, Demilitarized Zones (DMZ), internal segmentation, host intrusion detection, and data encryption at rest and in transit.

# 2.2 Firewalls, IDS, IPS, VPNs, and proxy servers

Perimeter defense coordinates five foundational network security technologies:

  • 1. Firewalls:
    • Stateless Packet Filters (Layer 3/4): Inspect individual packets independently against static ACLs (Source IP, Destination IP, Protocol, Port). Lacks awareness of connection states; vulnerable to ACK/FIN flag manipulation.
    • Stateful Inspection Firewalls (Layer 4): Maintains a dynamic Connection State Table tracking TCP flags (SYN, SYN-ACK, ESTABLISHED, FIN/RST) and sequence numbers. Unsolicited inbound packets not matching an active outbound session are dropped automatically.
    • Next-Generation Firewalls (NGFW / Layer 7): Integrates deep packet inspection (DPI), application awareness, TLS decryption, and inline malware sandboxing.
    • Linux iptables Example:
      iptables -P INPUT DROP (Default deny policy)
      iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
      iptables -A INPUT -p tcp --dport 22 -s 192.168.1.0/24 -j ACCEPT
  • 2. IDS vs IPS:
    • Intrusion Detection System (IDS): Passive monitor attached to a network TAP or switch SPAN (mirror) port. Generates alerts via syslog without modifying traffic flow.
    • Intrusion Prevention System (IPS): Active inline deployment. Inspects packets in transit and immediately drops malicious connections (injecting TCP RST flags).
    • Snort Rule Architecture:
      alert tcp $EXTERNAL_NET any -> $HTTP_SERVERS 80 (msg:"Possible SQL Injection"; content:"' OR 1=1"; nocase; sid:1000001; rev:1;)
  • 3. Virtual Private Networks (VPNs):
    • IPsec: Network-layer security using Authentication Header (AH - integrity/authentication) and Encapsulating Security Payload (ESP - confidentiality + integrity). Operates in Tunnel Mode (entire packet encrypted) or Transport Mode (payload only).
    • SSL/TLS VPNs: Application/Transport layer (OpenVPN, WireGuard) accessible via standard web browsers.
  • 4. Proxy Servers:
    • Forward Proxy: Intermediates outbound client requests, masking internal client IPs and enforcing corporate acceptable-use policies.
    • Reverse Proxy: Sits in front of internal web servers, handling SSL/TLS offloading, load balancing, DDoS buffering, and concealing real backend IP addresses.

  • 1. Firewall Ke 3 Generations:
    • Stateless Packet Filter: Aalsi chaukidar jo har aate-jaate packet ko akele dekhta hai static rules pe (IP, Port). Ise yeh nahi pata hota ki yeh packet kisi ongoing conversation ka hissa hai ya nahi. Attacker fake ACK flag laga ke ise fool kar leta hai!
    • Stateful Inspection Firewall: Smart firewall jo dynamic Connection State Table maintain karta hai. Jab internal computer bahar request bhejta hai (TCP SYN), toh yeh entry bana leta hai. Jab bahar se reply (SYN-ACK) aata hai, tabhi allow karta hai. Koi bhi unsolicited bahar se aane wala packet seedha DROP ho jata hai!
    • Next-Generation Firewall (NGFW): Layer 7 Deep Packet Inspection (DPI) karta hai. Yeh port number se dhokha nahi khata—agar port 80 pe BitTorrent chal raha hai, toh yeh packet ke content ko padhke block kar dega!
linux_iptables_stateful_rules.sh
# 1. Default Deny Policy: Jab tak explicitly allow na ho, har incoming packet drop karo
iptables -P INPUT DROP

# 2. Stateful Rule: Agar connection pehle se chal rahi hai (ESTABLISHED/RELATED), toh reply aane do
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# 3. Controlled Service: SSH (Port 22) sirf internal trusted subnet (192.168.1.0/24) se allow karo
iptables -A INPUT -p tcp --dport 22 -s 192.168.1.0/24 -j ACCEPT
  • 2. IDS vs IPS & Snort Signature Anatomy:
    • IDS (Intrusion Detection System): Passive monitor hota hai jo switch ke SPAN/Mirror port ya TAP pe baithta hai. Traffic wire se nikal jata hai, IDS sirf copy ko dekh ke syslog alert bhejta hai—traffic ko rok nahi sakta!
    • IPS (Intrusion Prevention System): Active inline device hota hai jo direct wire ke beech me baithta hai. Malicious pattern match hote hi packet ko live drop karta hai aur dono sides ko TCP RST bhej ke session kill kar deta hai!
snort_rule_dissection.rules
# Snort Rule Breakdown:
# Header: Action (alert) | Protocol (tcp) | Source ($EXTERNAL_NET any) -> Dest ($HTTP_SERVERS 80)
# Options: msg (Alert text) | content (Malicious SQL pattern) | nocase | sid (Unique Rule ID)
alert tcp $EXTERNAL_NET any -> $HTTP_SERVERS 80 (msg:"Possible SQL Injection"; content:"' OR 1=1"; nocase; sid:1000001; rev:1;)
  • 3. VPNs (IPsec AH vs ESP) & Proxies:
    • IPsec AH (Authentication Header): Packet integrity aur authentication deta hai par data ko encrypt nahi karta (clear text rehta hai).
    • IPsec ESP (Encapsulating Security Payload): Confidentiality + Integrity dono deta hai (poora payload encrypt). Tunnel Mode me poora IP packet encrypt hota hai; Transport Mode me sirf data payload.
    • Forward Proxy vs Reverse Proxy: Forward proxy client ke aage lagta hai (hostel/company internet filter aur IP mask); Reverse proxy (Nginx) web server ke aage dhaal ban kar baithta hai, backend server ke actual IP ko chupata hai aur SSL decrypt karta hai!

# 2.3 Vulnerability Assessment and Penetration Testing (VAPT)

Vulnerability Assessment and Penetration Testing (VAPT) provides an end-to-end framework combining broad automated scanning with targeted manual exploitation. The standard industry workflow proceeds across 6 discrete phases:

  1. 1. Scoping & Asset Discovery: Define in-scope IP subnets, domains, testing windows, and execute formal Rules of Engagement.
  2. 2. Automated Vulnerability Scanning: Deploy enterprise scanning engines (Nessus, OpenVAS, Qualys) to identify missing patches, default credentials, and misconfigured services against global CVE databases.
  3. 3. False-Positive Validation & Analysis: Manually verify automated scanner output via banner checks, manual parameter fuzzing, and proof verification to eliminate scanner hallucinations.
  4. 4. Controlled Exploitation: Formulate multi-stage exploit chains (e.g. leveraging an unauthenticated file upload to trigger remote code execution) to validate real business risk.
  5. 5. Risk Prioritization (CVSS Scoring): Assign contextual risk ratings factoring in exploit complexity, privilege prerequisites, and data sensitivity.
  6. 6. Remediation Guidance & Re-Testing: Deliver actionable remediation roadmaps to sysadmins, followed by re-scanning to certify that vulnerabilities have been patched.
Credentialed vs Uncredentialed Scans

• Uncredentialed Scan: Simulates an external adversary probing network boundaries without authentication. Finds open ports, exposed banners, and perimeter flaws.

• Credentialed Scan: Scanner connects using administrative SSH/SMB credentials. Inspects installed software registry entries, unpatched local binaries, missing kernel hotfixes, and weak filesystem permissions.

  1. 1. Scoping & RoE (Pehle Daayra Tay Karo): Client se formal agreement sign karwana ki kaun se IP subnets aur domains test karne hain. Production server ka peak time avoid karna aur Rules of Engagement me timing likhna.

  4. 4. Controlled Exploitation (Proof of Concept PT): Metasploit ya custom script use karke flaw ko exploit karna (e.g., unauthenticated file upload se web shell daal kar dekhna) bina database drop kiye taaki business risk prove ho sake.

  6. 6. Remediation & Re-Testing: Sysadmins ko exact patch command dena. 14 din baad re-scan karke certify karna ki flaw sach me fix ho gaya hai.

# 2.4 Packet sniffing

Packet Sniffing is the interception and decoding of network frames traversing a physical or wireless transmission medium. The mechanics depend on hardware operating modes and network topology:

  • Promiscuous Mode: In normal operation, a Network Interface Card (NIC) inspects the destination MAC address of incoming frames and discards frames not addressed to its hardware MAC or broadcast (FF:FF:FF:FF:FF:FF). In promiscuous mode, hardware MAC filtering is disabled, passing all observed network frames directly to the operating system kernel.
  • Switched vs Shared Networks:
    • Hubs (Shared Media): Broadcast every frame to every connected port; sniffing is trivially passive.
    • Switches (Segmented Media): Forward frames only to the physical port mapped to the destination MAC via the Content Addressable Memory (CAM) table.
    • Active Sniffing Techniques on Switches:
      1. MAC Flooding (macof): Flooding switch CAM memory with 100,000+ random source MAC addresses until table space exhausts, forcing the switch into a 'fail-open' broadcast hub mode.
      2. ARP Cache Poisoning: Forging gratuitous ARP replies to redirect target traffic through the attacker's NIC.
  • Packet Capture with tcpdump & BPF Syntax:
    tcpdump_cheatsheet.sh
    # Capture packets on eth0 on port 80 with numeric addresses
tcpdump -i eth0 -nn -v 'port 80'

# Capture only TCP SYN packets (connection initiation probes)
tcpdump -i eth0 -nn 'tcp[tcpflags] & (tcp-syn) != 0 and tcp[tcpflags] & (tcp-ack) == 0'

# Capture traffic to/from a specific target host and save to PCAP file
tcpdump -i eth0 -nn -s0 -w capture.pcap 'host 192.168.1.50'
  • Wireshark Display Filter Mastery:
    • http.request.method == "POST" (Isolate submitted passwords/forms)
    • tcp.flags.reset == 1 (Identify blocked or aborted connections)
    • dns.flags.response == 1 and dns.time > 0.5 (Detect slow or intercepted DNS queries)
    • Follow TCP Stream: Right-click any packet → 'Follow TCP Stream' reconstructs complete bidirectional application payloads (recovering cleartext credentials from FTP, Telnet, or HTTP).
🇮🇳 FOR BKL Mukul Explains · 2.4 Wireshark, tcpdump aur Promiscuous Mode Ka Khel

Packet sniffing ka simple matlab hota hai network wire pe chupke se kaan lagana aur passing data sunna! Lekin switched network me data sunna itna asaan nahi hota. Samjho kaise kaam karta hai:

  • Promiscuous Mode Ki Asli Science:
    Normal halat me tumhara Network Card (NIC) bada shareef hota hai—woh frame ka Destination MAC address dekhta hai. Agar MAC uska apna hai ya broadcast (FF:FF:FF:FF:FF:FF) hai, tabhi accept karta hai, baaki sab packets raste me hi dustbin me daal deta hai.
    Jab hum Promiscuous Mode on karte hain (ip link set eth0 promisc on), toh hardware MAC filter bypass ho jata hai! Wire se guzarna wala 100% data seedha OS kernel aur Wireshark/tcpdump ko forward ho jata hai!
  • Hub vs Switch & Active Sniffing:
    • Hub (Purana Jamana): Dumb device jo har frame ko sabhi ports pe blast karta tha. Yahan passive sniffing bacchon ka khel thi.
    • Switch (Aaj Ka Jamana): Intelligent device jo CAM Table (Content Addressable Memory) banata hai. Switch ko pata hota hai ki Port 1 pe kaun sa MAC hai aur Port 2 pe kaun sa, isliye packet sirf usi port pe jata hai.
    • Hacker Switch Ko Kaise Todta Hai:
      1. MAC Flooding (Tool: macof): Attacker 1 second me 1,00,000 nakli MAC addresses switch pe bombard karta hai. Switch ki CAM memory full ho jati hai aur switch pagla ke 'Fail-Open' mode me chala jata hai—matlab Hub ban jata hai aur sabhi packets har port pe broadcast karne lagta hai!
      2. ARP Cache Poisoning: Switch ko trick karke victim ka sara traffic apne computer ke through guzaarna.
tcpdump_bpf_command_breakdown.sh
# 1. Port 80 HTTP traffic capture karo numeric mode me (-nn se DNS lookup rukta hai, speed badhti hai)
tcpdump -i eth0 -nn -v 'port 80'

# 2. BPF Bitmask Filter: Sirf TCP SYN probes capture karo (port scans dhoondhne ke liye)
tcpdump -i eth0 -nn 'tcp[tcpflags] & (tcp-syn) != 0 and tcp[tcpflags] & (tcp-ack) == 0'

# 3. Target host ka poora raw traffic PCAP file me capture karo (-s0 se poora packet bina kate record hota hai)
tcpdump -i eth0 -nn -s0 -w target_traffic.pcap 'host 192.168.1.50'

# 2.5 Spoofing and man-in-the-middle (MITM)

Spoofing involves forging identity metadata to impersonate a trusted entity. A Man-in-the-Middle (MITM) position allows an attacker to intercept, inspect, and modify communications in real time:

  • 1. ARP Cache Poisoning:
    The Address Resolution Protocol (RFC 826) maps 32-bit IP addresses to 48-bit MAC addresses. ARP is completely stateless and trusts unsolicited Gratuitous ARP announcements without cryptographic validation.
    • Execution Mechanism:
      To Victim: Gateway IP (192.168.1.1) is at Attacker MAC (AA:BB:CC:DD:EE:99)
      To Gateway: Victim IP (192.168.1.50) is at Attacker MAC (AA:BB:CC:DD:EE:99)
    • Terminal Execution:
      echo 1 > /proc/sys/net/ipv4/ip_forward (Enable packet routing)
      arpspoof -i eth0 -t 192.168.1.50 192.168.1.1
      arpspoof -i eth0 -t 192.168.1.1 192.168.1.50
  • 2. DNS Spoofing & Cache Poisoning:
    Forging DNS responses to resolve trusted domain names (e.g., bank.com) to an attacker's malicious phishing IP. The Kaminsky attack floods resolvers with forged responses guessing 16-bit Transaction IDs and source ports.
  • 3. IP Address Spoofing:
    Manipulating raw IP packet headers to forge the source IP address. Used primarily in blind attacks, UDP amplification floods, and bypassing IP-based access control lists.
  • 4. SSL/TLS Stripping (`sslstrip`):
    Intercepting HTTP 302 redirects to HTTPS, downgrading links to cleartext HTTP for the victim while maintaining an encrypted HTTPS session with the legitimate server.
  • Defensive Mitigations:
    • Dynamic ARP Inspection (DAI): Switch validates ARP packets against the DHCP Snooping database, dropping unauthorized MAC-IP pairs.
    • DHCP Snooping: Drops rogue DHCP server offers on untrusted access ports.
    • HTTP Strict Transport Security (HSTS): Browser enforces HTTPS connections exclusively, blocking SSL stripping.
    • DNSSEC: Cryptographic signatures for DNS records preventing forged resolution.

  • 1. ARP Poisoning Ka Asli Flaw (RFC 826):
    ARP protocol 1982 me bana tha jab sab log shareef the. Isme koi authentication nahi hota! Agar koi computer bina maange bhi chilla ke bol de (Gratuitous ARP) ki 'Main 192.168.1.1 hoon', toh baki saare computers chupchap apni ARP cache table update kar lete hain!

Attacker us redirect ko intercept karta hai aur victim ko HTTP clear-text pe hi rakhta hai, jabki khud server se HTTPS pe baat karta hai! Victim ka password clear-text me leak ho jata hai!

    • Dynamic ARP Inspection (DAI): Switch ke level pe security. Switch har ARP packet ko check karta hai—agar ARP packet DHCP Snooping database se match nahi hua, toh switch use usi waqt drop kar dega!
    • HSTS (HTTP Strict Transport Security): Web server browser ko bolta hai 'Agli baar bina HTTPS ke connect hi mat hona'. Browser cleartext HTTP pe aane hi nahi deta, SSL strip fail ho jata hai!
    • DNSSEC: DNS records pe cryptographic digital signatures lagte hain jisse fake DNS reply reject ho jata hai.

# 2.6 System security: privilege escalation, backdoors, and Trojans

Once an initial foothold is secured on a host, an adversary executes system-level post-exploitation techniques to expand access and guarantee persistence:

  • Privilege Escalation Taxonomy:
    • Horizontal Privilege Escalation: Attacker assumes identity and permissions of another user at the identical privilege tier (e.g. User Alice → User Bob).
    • Vertical Privilege Escalation: Attacker elevates permissions from a restricted standard user account to full administrative control (e.g. www-data → root on Linux, or Standard User → NT AUTHORITY\SYSTEM on Windows).
  • Linux Privilege Escalation Vectors:
    • SUID (Set User ID) Binaries: Executables running with the permissions of the file owner (root) rather than the executing user:
      find / -perm -u=s -type f 2>/dev/null
      Vulnerable binaries (e.g. misconfigured find, nmap, vim) allow shell escapes.
    • Sudo Misconfigurations (`sudo -l`): Permitting standard users to execute specific commands without root password.
    • Writable Cron Jobs: Root cron scripts located in world-writable directories allowing malicious command injection.
    • Kernel Exploits: Memory corruption flaws in Linux kernel drivers (Dirty COW, Dirty Pipe).
  • Windows Privilege Escalation Vectors:
    • Unquoted Service Paths: Service binary paths containing spaces without quotation marks (e.g. C:\Program Files\Vulnerable Software\service.exe) allow binary planting.
    • Token Impersonation: Abusing SeImpersonatePrivilege via Potato exploits (PrintSpoofer, JuicyPotato).
  • Malware Architecture Classifications:
    • Trojans: Malicious executables masquerading as benign software (e.g., game patchers or PDF viewers).
    • Backdoors & Web Shells: Persistent administrative listeners (PHP/JSP/ASPX) embedded in web directories granting remote command execution.
    • Rootkits (Kernel-Mode vs User-Mode): Stealth software hooking system calls (e.g. sys_getdents) to conceal processes, files, and network sockets from system diagnostic utilities (ps, netstat, Task Manager).

# 2.7 Wireless network security and WPA/WPA2

Wireless (IEEE 802.11) security differs fundamentally from wired networks because the transmission medium is shared radio frequency (RF) broadcast space:

  • Evolution of Wireless Encryption Protocols:
    • WEP (Wired Equivalent Privacy): Catastrophically insecure. Utilizes RC4 stream cipher with an undersized 24-bit Initialization Vector (IV). IV space exhaustion leads to IV reuse, allowing algebraic recovery of the shared master key via Fluhrer-Mantin-Shamir (FMS) attack within minutes.
    • WPA (Wi-Fi Protected Access): Interim fix replacing WEP using Temporal Key Integrity Protocol (TKIP) with 48-bit IVs and per-packet key mixing.
    • WPA2 (IEEE 802.11i): Mandates Counter Mode with Cipher Block Chaining Message Authentication Code Protocol (CCMP) based on AES-128.
  • The WPA/WPA2 4-Way Handshake Breakdown:
    The handshake establishes dynamic encryption keys without transmitting the pre-shared key (PSK) over the air:
    1. Message 1 (AP → Client): AP transmits Authenticator Nonce (ANonce).
    2. Message 2 (Client → AP): Client generates Supplicant Nonce (SNonce), derives the Pairwise Transient Key (PTK) using:
      $$\text{PTK} = \text{PRF}(\text{PMK}, \text{ANonce}, \text{SNonce}, \text{AP MAC}, \text{Client MAC})$$
      Client transmits SNonce + Message Integrity Code (MIC) to AP.
    3. Message 3 (AP → Client): AP derives identical PTK, validates MIC, and transmits Group Temporal Key (GTK) + MIC.
    4. Message 4 (Client → AP): Client confirms key installation with ACK.
  • Handshake Capture & Offline Dictionary Cracking Workflow:
    aircrack_suite_workflow.sh
    # 1. Enable wireless monitor mode
airmon-ng start wlan0

# 2. Sniff target AP traffic on specific channel and record to file
airodump-ng -c 6 --bssid 00:14:6C:7E:40:80 -w capture wlan0mon

# 3. Inject deauthentication frames to force client re-association
aireplay-ng -0 5 -a 00:14:6C:7E:40:80 -c 00:26:08:12:34:56 wlan0mon

# 4. Perform offline dictionary attack against captured 4-way handshake
aircrack-ng -w /usr/share/wordlists/rockyou.txt -b 00:14:6C:7E:40:80 capture-01.cap
  • WPA3 Enhancements: WPA3 replaces the 4-way handshake with Simultaneous Authentication of Equals (SAE) based on the Dragonfly handshake. Provides Forward Secrecy and renders offline dictionary brute-forcing mathematically impossible even against weak passphrases.

Protocol Encryption Cipher IV Size Kamzori / Status
WEP RC4 Stream Cipher 24-bit (Chhota) IV collision hota hai, FMS attack se 5 min me crack! Bilkul dead.

  • WPA2 4-Way Handshake Ka Cryptographic Khel:
    Wi-Fi ka password (PSK) kabhi bhi hawa me radio waves pe transmit nahi hota! Router aur phone 4 messages exchange karke ek dynamic encryption key banate hain jise PTK (Pairwise Transient Key) kehte hain:
    1. Message 1 (AP → Phone): Router ek random number bhejta hai jise ANonce (Authenticator Nonce) kehte hain.
    2. Message 2 (Phone → AP): Phone apna random number banata hai jise SNonce kehte hain. Phir phone formula lagata hai:
      $$\text{PTK} = \text{PRF}(\text{PMK}, \text{ANonce}, \text{SNonce}, \text{AP MAC}, \text{Phone MAC})$$
      Phone PTK se ek Message Integrity Code (MIC) banake router ko bhejta hai.
    3. Message 3 (AP → Phone): Router bhi same PTK nikal ke MIC verify karta hai aur multicast ke liye Group Key (GTK) bhejta hai.
    4. Message 4 (Phone → AP): Phone confirm karta hai ki connection ready hai.
